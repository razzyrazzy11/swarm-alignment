# Sanitized public snapshot disclosure protocol, version 2

This protocol defines a separate, explicitly disclosed publication copy of the completed study. It does not amend the experiment, replace the registered private history, or authorize another provider call. The canonical source is commit `7c3f570fb89ffa685e495dce46349cc9caee4876`, tree `4f4a08d4c60361dfc68c945ab93be544a48a4bbb`.


Version 1 stopped before creating any candidate because its location plan missed canonical-JSON hash references, including a historical synthetic fixture. Version 2 retains that failed registration unchanged and adds exactly the 30 reviewed source-commitment metadata files. This repairs disclosure bookkeeping; it changes no study responses, statistical calculations or scientific findings. The failed attempt and its diagnostic records remain private.

## What the snapshot preserves

All released study data and recorded final model responses are retained byte for byte. This includes failed requests, usage flags, scientific costs and reservations. The original scientific production modules, parsing, scoring, bootstrap procedures and figure calculations are unchanged. One historical fixture test checksum literal is rebound as described below. The PDF and DOCX are the exact final artifacts previously verified on master. This disclosure does not produce another manuscript or replace its native Word export and recorded inspection of every PDF page.

The public verifier recomputes the MAIN report, generator sensitivity, historical analyses, source-bound figures and paper checks from the disclosed inputs. It distinguishes this mathematical replay from authentication of private provider records. Original native transport and protocol admission are privately attested; they are not publicly repeated by this route. Passing the public checks does not independently authenticate a provider's account or response history.

## What changes, and why

Nine research documents contain ten reviewed account-credit amount spans. Only those numeric spans are replaced with explicit redaction markers. Scientific costs, configured caps, spending floors, conversion rules and design decisions remain visible. Study final responses to bounded fake-data tasks are retained with the author's explicit permission. Hidden provider reasoning, private transport headers, credentials and native response identifiers are excluded.

Some source-commitment metadata transitively hashes a document containing a redacted amount. Publishing its original digest alongside almost identical redacted text could permit guesses at that amount. The snapshot therefore rebinds exactly the 30 reviewed source-commitment metadata files to the disclosed document bytes. These are disclosure derivatives, not the original Git-tagged freeze files. Their new hashes do not replace, backdate or validate an original registration. The manifest lists each changed path and its disclosed digest without publishing private value hashes or line guards. The original source, receipts, failed processing attempts, tags and history remain intact in the private canonical repository.

The original README and workflow definitions are retained under `provenance/`. A new README and one active snapshot workflow describe the new verification scope and commands. The snapshot contains no canonical Git history or private journal archive. It includes the prospective disclosure tools and protocol, with text committed using LF endings and binary artifacts unchanged.

The disclosed source-commitment closure reaches the manifest of a historical synthetic fixture and the single manifest-checksum literal at line 20 of paper/tests/test_integrity.py. Version 2 permits only that checksum metadata replacement in a copied test. The original private test remains unchanged. The issuer requires all other bytes to match and validates both versions against a fixed normalized AST signature. The checksum literal is replaced by a neutral sentinel before computing that signature, so the signature does not encode the withheld original digest. The historical fixture explicitly preserves its original line endings as test input. Public admission verifies that the disclosed literal matches the exact disclosed fixture manifest bytes and that all assertions and other AST nodes retain their original structure. No scientific production function or assertion is weakened. Any further Python or scientific-data change remains a blocking error.

## Prospective issuance gate

Before any real snapshot export or mathematical replay, the generic disclosure tools, tests and this protocol must be committed, independently reviewed and covered by focused normal and optimized Python tests. A prospective freeze at `research/public-snapshot-disclosure-v2-freeze.json` binds all those source bytes, the canonical commit and tree, and the tooling source commit. The lightweight tag `public-snapshot-disclosure-v2` must be pushed to the existing private canonical origin before issuance.

The issuer checks the exact canonical tree and file count, tooling ancestry, all reviewed source hashes, the freeze hash, the current exporter bytes and the actual remote tag identity. Private span guards, known private literals, permission maps and source-location plans remain outside the publication copy. The issuer fails closed on an unexpected field, source byte, secret match, unreviewed redaction or unresolved hash dependency. It does not call model providers, create repositories or change Git refs.

The export is a new private directory. Each original file is either unchanged, explicitly redacted, explicitly rebound or relocated under the manifest. New public tools, documentation, workflow and attributes have generated roles. The exact final PDF and DOCX hashes are mandatory. A private issuer receipt outside the candidate records the manifest and trusted-launcher digests. An unsuccessful candidate is preserved for diagnosis and never represented as a verified release.

## Reader verification and trust

Obtain two checksums from the author's separate release announcement: the manifest SHA-256 and the SHA-256 of `public_snapshot_v2/verify.py`. A checksum obtained only from the downloaded snapshot cannot authenticate that same snapshot. Check the launcher checksum with a separate trusted command before executing it.

Run the trusted launcher with Python `-I -B` and the externally supplied manifest checksum. Its standard-library-only preflight authenticates the full declared inventory before importing project code or installing dependencies. After preflight, install the admitted requirements. Run the focused synthetic tests and then the full verification in normal and optimized modes. The workflow uses separately configured `SNAPSHOT_MANIFEST_SHA256` and `SNAPSHOT_LAUNCHER_SHA256` repository variables for these pins; missing variables fail the check.

The launcher blocks Python network access and project-directory writes during verification. Full mathematical replay also rejects subprocess creation. It rejects extra files, nested Git repositories, bytecode caches, symlinks and missing or altered committed bytes; an ordinary root `.git` directory is allowed for a fresh clean clone. Reports must be new JSON files outside the admitted directory. A successful preflight or synthetic test run is not a successful scientific replay.

The manifest binds the author's private-check claims through their canonical digest. Its receipt binds back to the manifest digest. This is a checksum and explicit attestation scheme, not a digital signature. It relies on the separately obtained pins and the author's attestation for private admission. Final admission repeats the full inventory check after mathematical, figure and artifact verification.

## Privacy checks and limits

Issuance scans all disclosed bytes, structured fields and decoded container contents. Exact direct-root permissions apply only to recorded study final-output fields and the reviewed scientific report schema; nested archives do not inherit these permissions. Known private literals are checked without printing them. XML entities, JSON escapes, compressed PDF streams and archive paths receive explicit handling. Unknown fields and ambiguous encodings fail closed where the policy requires a known structure.

The checks cover reviewed account spans, forbidden field classes and the known values supplied privately to the issuer. They do not prove that every unknown secret is absent, guarantee anonymization, or erase copies previously accessible while the original repository was public. Generic privacy code contains no actual private-value hashes or guard plans.

## Release decision

Preparation and local verification do not authorize publication, a repository rename, public visibility changes or history rewriting. The private canonical master remains the authoritative original. Publication requires a concrete verified candidate and the author's final repository/publication decision. This is a later disclosure operation, not a new experiment or evidence that a submission deadline was met.
