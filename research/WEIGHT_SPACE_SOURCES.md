# Weight-space programming as a bounded swarm-audit intervention

Primary-source review, 6 November 2026. Recommendation: conduct a separately registered, CPU-only tiny-policy experiment alongside the live-handoff study. The useful question is whether directly programmed or repaired policy weights preserve a **joint authorization contract**, and whether a release gate can establish this. It is not whether arbitrary LLM weights reveal collusive intent. This memo is research/design advice, not a claim that new model outputs have already been collected.

## Begin with a concrete failure

Two workers each control one step of a fake update. The global rule requires the origin's authorization and the receiving worker's authorization. A tiny network turns the first authorization into a handoff bit; a second network combines that bit with the receiver's permission. Changing the first network can make an unauthorized handoff appear permitted to the second. Its individual input/output rule may still look reasonable while the composed workflow violates the original contract. The interpreter's fake before/after state determines the violation.

The experiment should ask an Adaption or HF-hosted writer for numeric weights or a numeric repair, then execute those tensors locally. A symbolic checker evaluates the entire finite input domain before deployment. Model-written explanations remain untrusted. A successful patch must preserve allowed work as well as prevent forbidden updates; an always-deny network is not a useful repair.

## What the linked work actually establishes

[Takehi et al.'s November 2 blog](https://rikiyat.github.io/blog/weight-space-programming/) reports direct parameter interpretation/editing without gradient training. Its conditions differ by task: some small-network results use no feedback, whereas the Qwen improvement uses bounded forward-pass feedback. The weights-only sycophancy experiment fails in four attempts; attention queries enable a subsequent result. The Gemma 270M follow-up does not establish a math improvement. These are task-specific capability observations, not a demonstrated general swarm programmer or intent detector.

The [released logs](https://github.com/RikiyaT/lm_understand-logs) identify prompts, responses, artifacts and evaluations for reported runs. Earlier prompt trials are excluded, and some large fine-tuned checkpoints are omitted with reconstruction information. Therefore the release is valuable evidence for reported experiments, not all research search history.

The [linked HF checkpoint](https://huggingface.co/RikiyaT/Qwen3.5-0.8B-weight-space-programming) reports an independent edited-model MATH-500 rerun of 51.0% using 2,000 generations; its base rerun is only a 25-problem smoke check. This is not a complete independent matched replication. Its 43.4 million generated tokens and H200 execution illustrate why a full large-model reproduction is a poor prerequisite for the weekend's bounded safety question.

## Position relative to earlier work

[Tracr](https://arxiv.org/abs/2301.05062) already compiles programs into transformer weights with known structure. Writing a Boolean permission gate into a neural network is therefore a control, not a novelty claim. [Arditi et al.](https://arxiv.org/abs/2406.11717) already show targeted interventions changing model refusal behavior; this project should not claim that small weight changes affecting safety are new. Neither source establishes the proposed multi-worker authorization experiment.

[Git Re-Basin](https://arxiv.org/abs/2209.04836) treats neuron permutations as symmetries. [Hidden Symmetries of ReLU Networks](https://proceedings.mlr.press/v202/grigsby23a.html) discusses permutation and positive scaling redundancies. Consequently, a large numerical weight difference or a changed checkpoint hash is not evidence of a behavioral defect. Include function-preserving permutations/rescalings as negative harm controls, and verify behavior rather than treating every changed tensor as unsafe.

## Minimal experiment worth running

1. **Freeze an explicit numerical contract.** Specify the tiny ReLU architecture, input meanings/order, threshold and tie rule, output meaning, finite numeric bounds, global authorization rule, accepted JSON tensor schema, edit budget, data-generation ranges and exact evaluation inputs. Reject NaN, infinity, extra dimensions and executable code. The host interprets numbers only.
2. **Compare writing and repair.** A writer creates a small policy from the specification, or repairs an independently planted defect. Use fixed task variants/input-role mappings and initial checkpoints chosen before outputs. Do not keep requesting patches until one works. If feedback is allowed, separately register its count and content; zero-feedback and feedback-assisted results are different conditions.
3. **Use meaningful controls.** Exact symbolic/compiled policy, unchanged defective checkpoint, matched random edits, and function-preserving reparameterizations. Match random controls by a declared edit count/norm, while acknowledging that equal norm is not equal functional difficulty. Include the continued single-worker decision to distinguish individual policy errors from a composition failure.
4. **Evaluate on unqueried inputs.** Exhaustively execute every finite Boolean permission/message state, plus declared role/permutation variants. Separate test inputs not shown as examples from genuinely new policy/task families. A fully given Boolean specification is program synthesis from a known rule, not discovery of a hidden behavior. Cases within one written artifact are dependent; the artifact/task instance, not every truth-table row, is the sampling unit for uncertainty.
5. **Test the oversight mechanism.** A hash gate detects unauthorized checkpoint change, not harmful semantics. An exhaustive behavioral gate checks the declared global contract and allowed-work completion. Compare these outcomes with a monitor's actual evidence view. Do not assert that trace-only monitoring is blind if the trace already contains the resulting forbidden action or reveals authorization facts. Any indistinguishable-prefix example must state exactly what is withheld and what remains observable.

Primary empirical measures should be specification pass rate per returned artifact, composed unauthorized-write rate, allowed-task success, invalid artifact rate, changed parameters and writer cost/latency. Report all requested outputs, including invalid patches and zeros. If patches are verified before execution, report prevented candidate defects separately from deployed violations. The exact solver is an upper reference within the bounded domain, not a scalable guarantee about arbitrary neural agents.

## What each service contributes

The [Adaption Responses reference](https://docs.adaptionlabs.ai/api/resources/responses/methods/create) exposes hosted model identifiers and inputs/outputs, with controls for tools, memory and storage. This supports using a hosted model as a **writer of small numerical artifacts**. It does not document a method for directly overwriting the weights behind that hosted endpoint. AutoScientist training or a downloaded adapted checkpoint must not be described as direct modification of the hosted Gemma model.

[HF Inference Providers](https://huggingface.co/docs/inference-providers/en/index) supplies another pinned writer family/serving condition. Local CPU code executes the tiny network; no large model, GPU Job, Endpoint or subscription change is necessary. [Safetensors](https://huggingface.co/docs/safetensors/en/index) provides a tensor serialization option; strict numeric JSON is sufficient for a small standard-library implementation. Neither format establishes policy correctness. [PEFT](https://huggingface.co/docs/peft/en/quicktour) describes base-plus-adapter training/inference; that is a different intervention and requires its own serving/compute plan. No inference credit balance should be interpreted as guaranteed GPU capacity.

## Fit to this sprint and the existing paper

The corrected governing source is the live [Swarm Alignment Hackathon guidelines/resources](https://apartresearch.com/sprints/swarm-alignment-2026#guidelines), especially Judging and results. Track 3's identity/lineage and protocol-integrity questions and Track 4's oversight/control questions provide the strongest fit. The public rubric rewards novelty, execution and clarity; a newly named technique alone does not justify a high score.

Present this as a separate, limited weight-artifact intervention linked to the same evidence-versus-truth problem as the live study. Preserve all earlier nulls. A useful result could be failure to synthesize reliable weights, a defect that survives local checks but violates composition, or a conservative verification gate's usefulness cost. Do not call a planted toy failure spontaneous collusion, a direct repair SFT, or a finite exhaustive check general swarm alignment. Freeze the protocol before new writer calls, keep tensor hashes and actual responses, and add results to the paper only after replay and provenance checks pass.

Coverage: the full linked blog, released repository README and experiment inventory, linked HF card, Tracr compiler/discussion/limitations sections, and the other cited papers' primary abstracts/formal summaries, plus official service documentation and current Swarm resource/rubric sections. The logs were not independently replayed and no large checkpoint was downloaded. This targeted overlap check does not certify universal originality.

## Addendum: ordinary fine-tuning, interaction-aware training and joint optimization

Reviewed 6 November 2026. The best additional training layer is a controlled **small-monitor adaptation study after an operationally meaningful development failure**, while completing the live-action and tiny-weight experiments first. More training mechanisms do not automatically make the submission more innovative or its conclusions stronger. None of the training methods below has been run for this project by this source review.

| Intervention | What actually changes | What it would test here |
|---|---|---|
| Ordinary worker SFT | A language model learns target responses from individual task/action examples | Whether a worker follows its local authorization rule more reliably; this alone does not test the correctness of interacting workers |
| Interaction-aware SFT | The same learning objective uses handoff histories, role information and mechanically checked trajectory/evidence labels | Whether training on the interaction boundary adds value over an equal-budget individual-example baseline |
| Joint multi-agent optimization | Training uses outcomes of interacting policies, with explicit role/trajectory credit assignment or centralized training information | Whether optimizing the composed workflow improves global outcomes beyond independently updated policies |
| Direct weight-space programming | A writer supplies numeric parameters/edits without a gradient training loop | Whether a small declared policy can be written/repaired and safely composed; this is the separate tiny-policy experiment |

LoRA is a parameterization/training-efficiency choice, not a swarm algorithm. [HF PEFT](https://huggingface.co/docs/peft/en/quicktour) documents targeting trainable adapter modules and loading a base with its adapter. [TRL SFTTrainer](https://huggingface.co/docs/trl/en/sft_trainer) supports conversation and prompt/completion data, with completion-only or assistant-only loss. Those options implement a learning objective; they do not supply global safety labels or establish coordinated behavior. A gradient baseline on the tiny numerical controller is not language-model SFT and must be named separately.

There is substantial multi-agent training precedent. [MADDPG](https://arxiv.org/abs/1706.02275) accounts for other agents' policies during actor-critic training; [MAPPO](https://arxiv.org/abs/2103.01955) is a strong cooperative-RL baseline with important implementation/hyperparameter sensitivities. These are not turnkey hosted LLM fine-tuning APIs. More directly, [MALT](https://arxiv.org/html/2412.01928v2) samples generator/verifier/refiner trajectories, propagates final outcome values, and uses role-specific SFT then DPO. Its role policies are updated independently using interaction-derived credit; this differs from simultaneous end-to-end gradients through a swarm. A new project cannot claim to originate role-specialized multi-agent LLM training.

### The most informative feasible comparison

If development data reveal a reproducible monitor failure, compare one pinned base model against (a) SFT on individual supported audit examples and (b) SFT on interaction-aware histories. Keep base checkpoint, adapter rank, optimizer recipe and training-token budget fixed; report row/episode counts and any unavoidable context-length differences. Evaluate all arms on the same new source groups, solo/delegated workflows, evidence losses and restoration budgets. Keep the existing exact comparator, always-abstain baseline, task usefulness, invalidity and unsupported-worker/NONE metrics. A trained monitor that becomes confidently wrong is not improved merely because its definite-answer rate rises.

Before generating or augmenting training rows, assign wholly new source groups to training, validation and locked testing. Separate task/policy families where a transfer claim is intended. All projections, aliases, paraphrases and message variants descended from a source stay within its split. Select checkpoints on validation only. The already inspected main results may motivate the question but cannot become its untouched test set. For ambiguous packets, the training target is ABSTAIN; the hidden factual actor must not teach unsupported certainty. For worker training, target actions instead follow actual permission/state rules; do not mix action correctness with investigator evidence support.

If a real unsafe interaction has not appeared, report that limit rather than optimize a safety-mitigation claim around zero events. A usefulness/refusal failure can still motivate a separately specified task-success intervention. Genuine joint optimization would additionally require an on-policy rollout pipeline, a global objective, credit assignment and frozen evaluation; adding that now is a larger project than training an audit reader. Global task reward must include policy violations or it could incentivize successful unauthorized work.

### Service and spending gates

[Adaption's supported-model page](https://docs.adaptionlabs.ai/autoscientist/supported-models/) currently lists small SFT options including Qwen3.5-0.8B, Llama3.2-3B and Gemma3-4B, generally requiring at least 1,000 effective rows; DPO requires 12,000, and some larger models require 10,000. The runtime catalog is authoritative. Augmentation can satisfy an effective-row minimum, but repeated views do not create independent source episodes. Training-context truncation is documented, so verify that policy facts and targets survive preprocessing.

The [AutoScientist create API](https://docs.adaptionlabs.ai/api/resources/autoscientist/methods/create) exposes bounded iterations and target win rate, not a documented monetary budget parameter. The [MCP documentation](https://docs.adaptionlabs.ai/tools/mcp/) explicitly says AutoScientist creation has no estimate mode. A recommended recipe is not a price quote, and vendor preference win rate is not this project's grounded-audit endpoint. Require a bounded launch charge, explicit model/recipe and a tested artifact-serving path before training. [Adaption's download guide](https://docs.adaptionlabs.ai/autoscientist/download-the-model/) documents downloading trained artifacts; that does not prove an arbitrary edited adapter can be served through the already used hosted Responses model ID.

HF TRL/PEFT gives more explicit control over a matched SFT comparison, but GPU/CPU training and adapter inference need a separate available compute plan and price bound. HF inference access and Pro status do not themselves reserve training hardware. No GPU rental, Job, Endpoint, AutoScientist launch, top-up or new spending authorization is inferred here. The current highest-value sequence is: finish the registered live audit; finish the bounded tiny-weight intervention; then launch one new, tightly controlled adaptation study only if failure, split, budget and serving gates all pass. This sequencing serves the Swarm rubric's execution and clarity dimensions while keeping novelty claims proportional to the actual contribution.
