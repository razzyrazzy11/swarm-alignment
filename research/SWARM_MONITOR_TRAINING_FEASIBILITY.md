# Small-monitor training: conditional feasibility, not a launched experiment

Checked 7 November 2026 against the primary sources linked below. This memo proposes a separate follow-up; it changes neither the frozen swarm-ledger protocol nor its primary endpoint. No new-study outcomes were inspected for this memo. No dataset upload, estimate POST, training, inference, permission change or account change was performed. Account balances and credentials are deliberately omitted.

**Read-only access update, 7 November 15:50 UTC:** the documented AutoScientist
model-catalog GET returned HTTP 200 with 16 entries. The smallest declared size
returned was `Qwen/Qwen3.5-2B`; `Qwen/Qwen3.5-0.8B` was not returned. Catalog
read access is verified; job-creation entitlement, award coverage and a training
price quote are not. See [SWARM_TRAINING_ACCESS.md](SWARM_TRAINING_ACCESS.md) for
the exact method, capability summary and private metadata provenance.

The research question remains **whether an auditor lacks evidence or fails to use sufficient evidence**. Training would address the second case only after the simpler prompt/procedure intervention leaves a reproducible failure. More spending or a trained artifact, by itself, supplies no additional scientific result.

## 1. What the available services actually establish

| Route | Documented capability | Important unresolved condition |
|---|---|---|
| Existing Adaption hosted inference | Bounded workers and fixed monitoring profiles in the registered study | Hosted inference access does not establish AutoScientist entitlement, price or deployment of an uploaded adapter. |
| Adaption AutoScientist | Documented managed SFT/LoRA and downloadable checkpoint; authenticated training-catalog GET returned 16 models, with 2B the smallest declared size observed | Read access does not establish launch entitlement. No estimate mode or currency spending-limit parameter was found for training creation; applicable quote and credit eligibility remain unverified. |
| Adaptive Data | Dataset adaptation with an estimate option | This is a data-transformation service, not a training quote. Estimate requests also save some dataset settings. |
| HF Jobs | GPU training and batch evaluation with explicit runtime limits | The inference token may lack Jobs permissions; hardware availability, remaining shared credits and compatible training kernels require verification. |

The official [Adaption MCP documentation](https://docs.adaptionlabs.ai/tools/mcp) explicitly distinguishes estimate-enabled data tools from AutoScientist creation, which has no estimate mode. The [training creation reference](https://docs.adaptionlabs.ai/api/resources/autoscientist/methods/create) exposes model, objective, hyperparameters, augmentation and iteration controls, but no documented currency cap. Setting `max_iterations=1` bounds iterations, not dollars. A hyperparameter recommendation is not a price quotation.

[Adaptive Data's adaptation reference](https://docs.adaptionlabs.ai/api/resources/datasets/methods/adapt) returns estimated credits and minutes with `estimate=true`, but saves mapping/expansion selections even then. It must not be described as a read-only GET. Do not use adaptation to rewrite authentic receipts, labels, missing-record masks or held-out tests. Deterministic oracle labels already provide the required targets.

## 2. Small checkpoint and serving compatibility

The [AutoScientist supported-model planning list](https://docs.adaptionlabs.ai/autoscientist/supported-models/) includes `Qwen/Qwen3.5-0.8B` and a 1,000-row minimum, but explicitly defers to the runtime catalog. The actual authenticated GET returned no 0.8B entry. It returned `Qwen/Qwen3.5-2B` with declared size 2B, SFT/DPO, LoRA/full and reasoning-training support. Thus **2B is the currently observed Adaption small-model candidate; 0.8B is only a static planning entry for that service**. Do not transfer the static 0.8B row minimum or other limits to the 2B model: the runtime response did not establish its minimum training size. Other returned models do not justify choosing whichever later scores best. The [runtime catalog schema](https://docs.adaptionlabs.ai/api/resources/autoscientist/methods/list_models) supplies capabilities rather than a training price.

The [official Qwen 0.8B model card](https://huggingface.co/Qwen/Qwen3.5-0.8B) identifies open weights under Apache 2.0 and describes text-serving paths. This remains a possible **separate HF/open-weights route**, not verified Adaption training availability. Its current architecture/software requirements make an actual compatibility smoke check necessary. An Adaption 2B route requires its own exact base revision, license/software and serving checks. Pin a model revision, tokenizer/chat template, dependency versions, container digest and dtype; do not depend on an unversioned latest environment. GPU memory fit and training duration have not been measured here.

For an interpretable intervention, compare **the same tiny checkpoint before and after one fixed adapter** on identical fresh packets, using the same local batch-inference implementation and decoding settings. An Adaption-trained 2B adapter cannot be treated as a matched intervention on a 0.8B base. Comparison against a larger hosted monitor is descriptive, because model, backend and size also differ. This tests a behavioral effect of changing a checkpoint; it does not show that weight inspection reveals swarm intent.

**Monitor SFT changes the auditor's policy, not the actors' checkpoints or the swarm's behavior.** It cannot establish that actor or joint-swarm fine-tuning changes coordination. That separate question changes the trajectory distribution and useful task completion; it needs a new actor/monitor factorial protocol, fresh source blocks and its own freeze. Neither intervention may be folded into the current main experiment retrospectively.

Adaption's [checkpoint-download documentation](https://docs.adaptionlabs.ai/autoscientist/download-the-model/) describes a downloadable archive, with LoRA weights/configuration among typical contents. Download availability does not establish that the existing hosted inference endpoint will serve that artifact. A practical independent route is HF GPU batch evaluation with PEFT; [PEFT model loading](https://huggingface.co/docs/peft/main/en/tutorial/peft_model_config) documents loading an adapter with its base. [vLLM's adapter support](https://docs.vllm.ai/en/latest/features/lora/) is another possible serving route, but exact architecture/adapter compatibility must be tested. Publishing a Hub repository alone does not make a custom adapter available through the current HF router condition.

## 3. Conditions for a scientifically useful follow-up

First complete and admit the registered experiment. Separate provider/usage/model anomalies, malformed output and missing-evidence ambiguity from semantic errors on sufficient evidence. A format-only problem warrants format controls; appropriate abstention on genuinely ambiguous evidence is not a reasoning failure.

A reasonable **prospective trigger proposal**, to be registered before any follow-up data, is a nontrivial count of admitted, semantically parseable errors that persist after the procedure prompt on FULL16 or the sufficient seven-receipt view, spread across independent base blocks and more than one stratum. Set the numerical threshold and a fixed fresh confirmation workload in that registration. Do not tune either after looking at confirmation outcomes, choose the model from main-result rankings, or call a single anecdote reproducibility. No threshold in this memo is an amendment to the current protocol.

If the trigger is met, use this sequence:

1. Freeze a new training/evaluation protocol, model revision, resource limit and checkpoint-selection rule. Stage 1 becomes prior exploratory evidence for this follow-up, not its untouched test set.
2. Generate separate TRAIN and VALIDATION source blocks with new namespaces, identity permutations and times. Keep every view, arm/counterfactual and wording variant derived from a base block in that block's split. Hash exact-example and structural-context joins to detect leakage. A random split of individual monitor calls is insufficient.
3. Produce targets with the independent finite-domain oracle. A singleton support set gives its definite label; multiple possible labels require ABSTAIN. Include positive and negative worlds, ambiguous evidence and identity joins. Describe simulated training worlds as simulated; do not present them as agent-executed empirical incidents.
4. One concrete scale to cost before registration is 320 training blocks with four prespecified simulated worlds and seven views, 80 validation blocks constructed independently, and 160 entirely fresh agent-executed test blocks with four assigned arms. These are proposed sizes, not generated data or a power calculation. Layout/identity siblings stay together. The training rows exceed the documented minimum without pretending that views create independent source blocks.
5. Use one fixed SFT/LoRA recipe and a validation-only selection rule. The [TRL SFT documentation](https://huggingface.co/docs/trl/sft_trainer) supports prompt/completion data with completion-only loss and PEFT adapters. Preserve the original verdict parser, class definitions and evidence boundary. Teacher text or generated reasoning must not substitute for host truth.
6. Freeze and hash the selected adapter before collecting/evaluating the fresh test blocks. Compare base and adapter on the same FULL16/sufficient packets. Retain all assigned cases and technical failures. Report supported correctness, correct definite verdicts, exact attribution, unsafe NONE, strict-format compliance, utility/cost and block-level paired uncertainty. Training's internal win-rate metric is not this project's test result.

Fresh agent-executed tests retain all four worker profiles (from three families), policy strata and layouts. Sample sizes must be divisible across the 40 strata, and uncertainty must resample base blocks, not views or repeated readers. Do not add these blocks to the ledger study's fixed 640-block primary analysis. If extra balanced-negative/positive simulated challenges are useful, label them as a separate diagnostic distribution.

## 4. Cost controls and entitlement checks

**Adaption:** protect the registered study's existing reservations first. Obtain the applicable training-credit terms and a binding maximum/quote for the selected model, dataset and single iteration before launching. Public documentation does not establish such a hard cap, nor an exchange rate between every product's credits and dollars. Do not transfer the hosted inference price schedule to training. The [running guide](https://docs.adaptionlabs.ai/autoscientist/running-autoscientist/) states that its four-hour SDK wait timeout stops waiting rather than training; a client timeout is therefore not a financial stop. No training quote or entitlement has been obtained in this task.

For the smallest auditable training treatment, propose explicit `model`, instruction SFT, zero optional augmentation and one iteration, then preserve the resolved configuration and artifact hashes. AutoScientist co-optimizes a recipe; absent a frozen recipe it would test a bundled training intervention, not isolate one learning algorithm. A succeeded run also need not mean its target was reached; [the overview](https://docs.adaptionlabs.ai/autoscientist/overview/) distinguishes success from attainment of the optimization goal.

Journal creation before sending and reconcile uncertain acknowledgements rather than retrying blindly. The [creation API](https://docs.adaptionlabs.ai/api/resources/autoscientist/methods/create) limits its idempotency-key deduplication to an in-progress run; reusing the key after a terminal run can launch another billed run.

**HF:** [Jobs billing](https://huggingface.co/docs/hub/en/jobs-pricing) currently lists T4-small at $0.40/hour and one L4 at $[private account value withheld]/hour, charged by the minute while Starting/Running. Positive compute credits can fund Jobs, including subscription compute credits. Current account allowance and hardware were not queried. The [configuration documentation](https://huggingface.co/docs/hub/en/jobs-configuration) requires Jobs-managing permission, documents automatic runtime timeout and defaults to one attempt. An inference-scoped token is not proof of that permission.

A planning envelope of one non-retrying L4 job with a 60-minute timeout is approximately $0.80 of GPU runtime; reserve additional margin for billable startup/minute rounding and any separate storage. This is **not** a measured duration, completion promise or provider-enforced dollar cap. Set one active job, no exposed ports, no scheduled/automatic retries and an explicit timeout. Verify the current hardware rate through documented `GET /api/jobs/hardware`, preserve outputs/checkpoints before ephemeral storage disappears, and reconcile actual charges. Do not spend the HF balance reserved for completing the original and new reader conditions. If no spare allowance/permission exists, leave training unlaunched rather than create another incomplete comparison.

## 5. Deadline and Sprint positioning

The [Sprint guidelines and judging/results section](https://apartresearch.com/sprints/swarm-alignment-2026#guidelines) prioritize impact/innovation, execution and clarity; require empirical variance/baselines, the official PDF template and the limitations/dual-use appendix; and judge the weekend's contribution. More model training does not automatically improve any dimension. The strong Track 4 claim would be a controlled reduction in **sufficient-evidence** errors on new swarm trajectories, while correctly preserving uncertainty when evidence is missing.

The submission cutoff is 8 November 23:59 AoE, equivalent to **9 November 11:59 UTC**. Proposed operational cutoffs: by 8 November 12:00 UTC require an admitted Stage 1 failure, quote/permissions, compatibility and frozen follow-up plan; by 18:00 UTC require a completed validated adapter and an untouched test design; by 9 November 06:00 UTC require completed tests and reproducible analysis. These are planning margins, not existing experiment commitments. Queue/training/download time has no verified guarantee. If these gates are not met, report the completed audit study and make this a clearly unrun secondary proposal.

Keep the paper's causal chain short: sufficient evidence → residual monitor error → fixed training treatment → fresh paired evaluation → bounded implication. Include negative results and changes in benign one-unit task completion. Attribute preexisting engines/models and new weekend code separately. Discuss that sharper monitor diagnostics can also help adversaries identify evasion conditions; all actions remain bounded fake-data operations, with no live targets or credentials in datasets.
