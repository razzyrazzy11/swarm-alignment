## Material clarification: when native admission occurred

The source supports full private/native validation **during export**, but the later default paper verifier should not be described as freshly repeating that full validation. `experiments/offline_release_supervisor_v2.py:15-22,39-60` dispatches the HF and MAIN export stages before the other five. HF `experiments/offline_release_recovery_v2.py:104-112,116-132` calls `collection.private_completed()` before projection; `experiments/hf_completion_v3.py:73-100,117-130,251-278` checks prefix/complement and completed union, and `experiments/hf_completion_v2.py:117-137` validates native normalization and associated receipt/body information. The MAIN `experiments/paced_resume_analysis.py:107-150` calls `admission_main()` before serialization; `experiments/swarm_ledger_paced.py:157-181` enforces a disjoint completed union. These source paths, successful retained stage outputs and the owner record support the registered export-time process; they do not independently prove provider truth or rule out a compromised host.

The retained V2 owner state has status complete, seven completed stages and zero inference calls (raw SHA-256 `2746de714fd0289f3f4da45ede6d4648e730c454d34f2d998afd9e2402efcd41`). The HF and MAIN export stdout JSON report valid (raw hashes `bdb6a7f15373ce268b8c8865427dba8c914e4a66aec311f93e7ed82aba8d6b1e` and `f38d774322ed52425015988b3c6ac0d5ec01feb1e1d58a35981dc9ba52dfd140`). The HF and MAIN release proofs report successful frozen verification with zero inference (raw hashes `6c2045cedcbcf4b30c224253d91e5113464d7dc64ce578f45b5a9572ca9474c7` and `3bfdc7de1216bcd72d1f5f62f7a4b6129aa1ecd1b39b8e511eb5cd3a41eb3522`). This review did not re-run full native admission or inspect all private journals; no specific corruption or omitted export-time native call was observed.

By contrast, `paper/verify.py:321-332` invokes `validate_results`, then `paper/complete_report_contract.py:122-168` invokes `recovery.verify()` and `verify_projection(replay=False)` by default, followed by public analysis replay. V2 `verify()` verifies registered source, parent and failed-waiter evidence, including private stopped-state/log commitments and process termination; its `collection.verify()` verifies registration, not `private_completed()` (`experiments/hf_completion_v3.py:117-130`). The later `paper/prepare_complete.py:103-172` issuance gate additionally checks the completed owner, source and driver liveness, projection proof, figures and public mathematics, but does not call `recovery.hf_completed()` or `paced.admission_main()` to repeat every native journal check. Thus `paper/content.json:113,140`, `research/PAPER_PUBLIC_REPLAY_PROTOCOL.md:4-8,55-57`, and comments in `paper/public_replay.py:3,323-328` can be read as claiming a fresh full native admission that these paths do not perform. The frozen `paper/complete_report_contract.py:123-126` docstring also understates its default private failed-waiter reads. This is an evidence-scope/wording issue, not demonstrated data corruption or a silent fallback.

Recommended current paper wording: “Default local verification checks retained private failed-waiter evidence and provenance together with public replay; it does not repeat full native-journal admission. Native-journal validation occurred during the V2 exports and requires the private archive.” Preserve the registered source/protocol and receipt; correct their interpretation in a separately recorded erratum or a prospective registered amendment if source changes are desired. The existing README statement that V2 projects after native admission describes the export sequence correctly.

## Boundaries and provenance

V2 validates `next_delay_seconds` as present, numeric, finite and nonnegative, removes only that field, then delegates to frozen V1 (`experiments/offline_release_recovery_v2.py:90-112`). V1 requires a unique exact identity/body inventory, rejects unexpected row/transport fields, validates diagnostics, and projects the explicit scientific and public transport allowlists (`experiments/offline_release_recovery.py:109-127`). The frozen public HF verifier is called after export and the proof binds public supplement/report bytes, private batch commitments, driver commitments and verification result (`experiments/offline_release_recovery_v2.py:116-154`). `experiments/hf_completion_v3.py:117-130` requires an exact disjoint pending complement; `experiments/swarm_ledger_paced.py:157-181` rejects repeated union identities. The reviewed path does not authorize replacement of failed IDs. This is code-path and retained-proof evidence, not a separate row-by-row journal audit.

Supervisor admission checks registered recovery, unused targets, stopped predecessor processes, driver states and absence of collector locks before creating a new owner directory; an existing directory is refused and child failure ends the run without retry (`experiments/offline_release_supervisor_v2.py:25-63`; `experiments/paced_resume_supervisor.py:32-49`). Owner and preserved public attestation require the exact seven ordered stages (`paper/prepare_complete.py:103-157`; `paper/public_replay.py:258-292`).

Public verification is explicit: `paper/verify.py:321-350` requires a boolean/CLI flag and forbids recording PDF metadata in public mode. Public admission verifies fixed schemas, source/parent inventories, tag bytes and ancestry, artifact hashes, owner attestation, and unchanged HF, figure and sensitivity reconstruction (`paper/public_replay.py:105-183,217-255,273-319`). Issuance calls the private `ready()` gate first, checks the strict figure-input schema and exact bytes, and validates its candidate before creating either artifact (`paper/public_replay.py:322-348`). `paper/tests/test_public_verify_mode.py:41-100` covers explicit routing and failure without fallback; `paper/tests/test_public_replay.py:59-277` includes mutations, tag/source, field allowlists, issuer ordering and lack of private-state reads. These are synthetic tests; this review read their scope but did not rerun them.

Registration source hashes normalize CRLF to LF, while artifacts, private states, figure receipt and supervisor owner commitment use raw bytes. This distinction matters: current `paper/verify.py` raw SHA-256 is `2ff9887d9c5fc6a8cb00bfb5baf425987eb991010bf8e87d1b64ce7a213668db`, LF-normalized `15ff8a91661c76825224928750ceb5a737e49cc69b4bf997ade99d9bb2f0c42c`; the V2 supervisor raw is `c99a2ac4168c09eb81f1f23e92814424c141d62c22e9792e67fb42bf12cdc312`, normalized `52f28b5b2f1a0870a59c5780751df1472b2848f3f5c6cca48b4c8dada7ca0dce`. See `paper/public_replay.py:61-62,105-114,168-177,258-266` and the CRLF-specific test at `paper/tests/test_public_replay.py:186-230`. Hash equality is a byte/lineage commitment, not independent authentication of a provider or host.

The published figure input includes an absolute executable path with a user-home component: operational machine/user metadata, despite the strict field-name allowlist (`paper/public_replay.py:186-203`). The path is not reproduced here. This does not establish a credential, native response ID or raw-answer leak. It means the packet should not be called fully anonymized. Its exact bytes are frozen and committed, so changing them would require a prospective amendment, not silent rewriting. `git ls-files runs/` returned zero tracked paths. This targeted check and schema inspection are not an exhaustive secret scan of every tracked byte or proof that no sensitive data exists anywhere.
