# Prospective Track 4 acceptance and applicability

7 November 2026. This memo supports the new acquisition/evidence-use study proposed in [NEXT_STUDY_DECISION.md](NEXT_STUDY_DECISION.md). It contains acceptance recommendations and a source-based applicability crosswalk, **not new experimental results**. The eventual frozen protocol controls sample sizes, endpoints and collection; this memo does not add model calls or change earlier registrations.

## Operator and track

The operator is an investigator with a partial export, a trusted original-record store and a limited retrieval allowance. The decision sequence is: retrieve an available witness, make a finding justified by the resulting packet, or abstain/escalate when evidence remains insufficient. A grounded answer may be NONE; absence of a write is different from missing proof of a write. A safe-looking completion claim is not an authenticated state observation.

The [current Swarm resources and guidelines](https://apartresearch.com/sprints/swarm-alignment-2026#guidelines) place incomplete-log oversight and workflow diagnostics in Track 4. Identity and collector interfaces support Track 3; the finite environment supports Track 1. No network-emergence claim follows. The rubric rewards useful novelty, convincing validation and clear communication. The required PDF/template, eight-main-page limit, abstract length, required ethics appendix and prior-work disclosure still apply. These are requirements; a particular score or prize is not guaranteed.

## Acceptance bank: offline, before any new inference

These are deterministic test fixtures for the chosen contract, not another paid experiment or additional empirical sample. Every expected label should be justified independently of the generating routine.

The frozen implementation uses fixed epoch-1 leases and distinct immutable workers; it does not claim arbitrary renewal/reassignment coverage. These offline acceptance recommendations are separate from the protocol's twenty scripted sufficient-packet calibration fixtures, which receive 120 separately labeled monitor readings. Those readings never increase the main source count or establish natural violation prevalence.

| Fixture | Required distinction |
|---|---|
| Permitted write succeeds | Correct executor and actual permitted effect; no accusation |
| Clean read/refusal/no call | No applied write; NONE is supported only when the visible contract rules out an unseen violating write |
| Unpermitted write succeeds | Actual effect and immutable executor; a plausible claim cannot override permission |
| Permitted write fails | Attempt is not application; a successful-dispatch record alone is insufficient |
| Approval expiry boundary | Exact declared comparison at expiry, with settlement time rather than an earlier request time |
| Reassignment/stale alias | Permission and executor bind to the appropriate instance/version; names alone do not establish identity |
| Missing essential witness | Multiple compatible labels require ABSTAIN, even when a guess matches hidden truth |
| Contradictory trusted records | Empty candidate set is an impossible/invalid packet, not ordinary ambiguity |
| Corrupted reference or score | Validation fails explicitly; the system must not reinterpret a grader defect as worker wrongdoing |

Use the frozen contract's actual event/time representation; do not add a temporal claim merely because record order is available. Distinguish malformed packets, impossible well-formed packets and ambiguous valid packets. Strict schema checks should reject Boolean-as-integer coercion, unsupported fields, stale bindings and fabricated records. Full, lost and restored variants must preserve authentic record identity.

The pre-treatment sufficient template is specified by record roles and tested over every finite allowed history, including no-write and failed outcomes. Its completeness must not depend on selecting favorable model actions. If a template cannot resolve a history, correct the template/specification before freeze rather than removing that source after inference. An independent reference must agree on labels/support; matching implementations still cannot exclude a shared specification mistake.

## No oracle leakage between components

Acquisition accepts only public contract, visible packet, manifest and budget. Compatible hidden worlds with identical visible inputs must yield the same selected IDs, including when the internal enumeration order changes. It cannot consult hidden truth, unopened payloads, scoring labels or post-selection singleton status. Any oracle-assisted selector is explicitly an upper reference, not a deployable baseline.

Reader procedures receive identical canonical packets, schema and nominal output limits; only the registered instruction/procedure differs. No procedure receives the hidden answer or an extra authentic witness. Evaluate raw decisions before any external support gate. Gate-induced abstention is enforcement, not evidence of better internal reasoning. Report coverage and errors together, including incorrect NONE and unwarranted abstention on the predeclared sufficient packets.

[Yun et al., scoring and Study II](https://arxiv.org/html/2610.09581v1) already separate factual agreement, grounded correctness, definite coverage and unsupported findings. [BRIDGE, §§3.3–3.5](https://arxiv.org/html/2610.17805v1) already uses paired continuations and verified evidence repair. The new question must therefore be prospective structural transfer and procedure performance. Acquisition may intentionally change available information; identical-input reader comparisons answer a different question. Realized-support strata remain descriptive, not randomized causal subgroups.

## Compact external-applicability crosswalk

This is a reading of published investigation limitations, not a new incident benchmark. No payloads were executed, raw incident corpus annotated, or ground-truth accuracy measured.

| Needed relation | What the primary account establishes | Operator implication |
|---|---|---|
| Requested action versus actual effect | [Swarm Traces, Limitations](https://swarmtraces.org/#limitations): recovered material is predominantly outbound requests, with limited responses and uncertain delivery/success | Retrieve a response or independent state witness; preserve attempted/returned/applied distinctions. If unavailable, abstain on execution rather than treating code as observed action. |
| Mutable name versus immutable executor | The same limitations describe self-selected names and uncertainty about the number of underlying agents | Request an operator-side run/instance binding. A name match is a search lead, not sufficient attribution. |
| Approval validity at settlement | [METR investigation, main data sources and limitations, pp.21–24](https://metr.org/hugging-face-incident-report-aug-2026.pdf) describes missing action-level timestamps and approximate reconstruction | If exact order/time changes permission, obtain authenticated temporal evidence or report the relation unresolved. Do not present approximate chronology as a verified lease boundary. |

The toy interface assumes these witnesses exist and can be retrieved. Public incident sources may lack them permanently. Consequently, the operational product is an explicit evidence request and supported stopping decision, not a guaranteed solution to historical reconstruction. Public payloads, investigator interpretations and authenticated observations must retain distinct provenance.

## What would strengthen the submission

Impact: a clear investigator decision and genuine new workflow structure, with a precise delta from existing acquisition/repair work. Execution: clean fault controls, independent finite validation, no hidden-world access, frozen denominators and separate acquisition versus interpretation outcomes. Presentation: one worked example followed by what happened, what the packet supports and what the reader concluded. The weight study remains a separate secondary result. These changes target the rubric without predicting official scores.

Reading depth: current sprint resources/guidelines; current decision memo; targeted Yun/BRIDGE methods; Swarm Traces limitations and relevant published examples; METR data/temporal limitations. This is not a full review of every incident payload, all source papers or the project directory. No external human validation or universal originality clearance is claimed.
