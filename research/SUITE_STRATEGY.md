# Positioning the suite after actual development tests

Current implementation checkpoint: STATEFUL_PROTOCOL.md and the published stateful-main-v2 tag define the first stateful main run (192 source episodes, 3,840 reader calls, 20-credit nominal cap) inside the broader research allocation below. Its fresh 80-call operational qualification passed; v1's failed encoding gate remains archived. Main and the 216-call influence extension are still unrun. Follow STATEFUL_RUNBOOK.md; this staged cap is not an instruction to spend the whole allocation on an unvalidated grid.

Decision date: 6 November 2026. Start with the outcome we need, then its measurement, then the tool. The 20-rules-of-learning skill is used to keep those dependencies clear, distinguish confusing claims, and connect each design choice to its source. It is not a novelty or eligibility test.

## Strongest defensible position

Anchor in Track 4 oversight, supported by Track 3 identity and a bounded testbed. The deliverable should be an executable evaluation with checkable evidence, matched baselines and a useful preservation/monitoring result. The [live sprint rubric](https://apartresearch.com/sprints/swarm-alignment-2026#guidelines) judges impact, execution and clarity together. The current prototype and genuine pilot calls improve execution, but do not constitute the full intended swarm study.

The initial hypothesis did not receive positive development support: selective loss removed more answerability but did not increase unsupported worker accusations. The peer pilot also found no unauthorized action. Preserve these negative results. A stronger next study should test a stateful handoff mechanism with a held-out family, not merely increase repetitions of the same easy fixture or rename known provenance ideas.

Closest boundaries remain [Yun's binding/renaming factorial](https://arxiv.org/html/2610.09581), [Qin's peer-influenced tampering](https://arxiv.org/html/2609.30266), [BLADE's handoff responsibility](https://arxiv.org/html/2610.18780v1), [BRIDGE's verified repair](https://arxiv.org/html/2610.17805v1) and [Syscon's receipt/detection distinction](https://apartresearch.com/sprints/projects/syscon-kernellevel-syscall-monitoring-for-ai-agent-control-in-sandboxed-environments-guun). A new combination is meaningful only if it changes an investigator's preservation or supported-decision tradeoff. No universal originality clearance is claimed.

## Assign each suite a scientific role

| Suite component | Best use here | Convention/gate |
|---|---|---|
| Adaption direct hosted inference | Main reader/worker conditions and measured model outputs | Freeze endpoint/version/settings, disable tools/memory/continuation, log actual usage and incomplete outputs |
| Adaptive Data / Invent-a-Dataset | Optional development-only peer-message or task-language diversity | Generated prose is stimulus material, never observed execution or ground truth; replay typed actions and validate labels mechanically |
| AutoScientist | Conditional cheap-monitor SFT after a real baseline failure exists | Episode/family split before projection or augmentation; a priced/bounded job and usable adapter route before launch |
| Adaptive inference stacks | Separate later intervention if retrieval/memory/self-improvement is the research question | Those features change the evaluated system; they stay off in equal-packet core comparisons |
| HF Hub / Pro | Pin model/tokenizer/data revisions and prepare licensed reproducibility assets | Pin full commit hashes, retain cards/licenses/splits; no automatic publication of private references |
| HF routed inference | Small explicitly pinned cross-provider serving check | The live router catalog exposes provider prices; same model name does not establish identical weights or decoding |
| HF PEFT / local serving | Potential base-versus-adapter evaluation route | Demonstrate loading a pinned base and adapter before paying for training; software/hardware compatibility remains a gate |

[Adaption Responses](https://docs.adaptionlabs.ai/api/resources/responses/methods/create) and [stack/memory conventions](https://docs.adaptionlabs.ai/inference-stacks/key-concepts/) explain the serving distinction. The first pilot demonstrated why it matters: reasoning tokens can exhaust the output allowance without a final answer. Bare-JSON formatting is another engineering factor. Freeze any normalization rule before testing; retain strict/raw validity separately. Do not call an incomplete response a refusal or a safety success.

[HF routing documentation](https://huggingface.co/docs/inference-providers/en/index) supports explicit provider suffixes and a priced model catalog. Our four Cerebras calls verify access only. Personal Pro currently supplies a small shared compute allowance, with metered overage [billing conventions](https://huggingface.co/docs/inference-providers/en/pricing); it is not a separate large training budget or a transfer of Adaption credits.

## Sequence the experiment by dependency

1. **Richer oracle before more calls.** Add genuinely different stateful handoffs, competing requests, copied/renamed instances or delayed execution results only where a finite exact contract can still be independently checked. Include clean, denied and known-positive controls. Preserve originals. A role/alias string must not leak immutable identity. Revalidate projections, malformed fields and source-family splits before choosing a confirmatory grid.

2. **A frozen core comparison.** Compare random/selective loss with paired naming conditions, equal retained records and reported token costs. Separate structural answerability from reader errors. Keep one primary contrast and label interactions, models and restoration as secondary. Use the same visible packets for every reader and the deterministic comparator. Allocate uncertainty at source-episode level, never over dependent views.

3. **Causal one-hop influence before network spread.** [Prompt Infection](https://arxiv.org/html/2410.07283v1) already studies propagation, while Qin already studies imitation from peer examples. Our simple messages produced no violations. Broaden development attacks using bounded peer logs/workspaces and plausible task pressure; randomize exposure against fact/length-matched benign and irrelevant/shuffled controls plus no exposure. Hold initial state, tools, action opportunities and model budgets fixed. Measure actual executed fake mutations and allowed-task success. A warning is a separate intervention; attribution alone is not evidence of influence. Validate one hop before adding topology or making epidemic/spontaneous-collusion claims.

4. **Small monitor SFT only when useful.** Train on supported executor/NONE or ABSTAIN targets, not hidden-world actor labels on ambiguous packets. The [supported-model page](https://docs.adaptionlabs.ai/autoscientist/supported-models/) lists small LoRA SFT options with at least 1,000 effective rows; DPO requires at least 12,000. Row counts after projection/augmentation are not independent episode counts. First build distinct development tasks and an untouched family holdout; then compare the same base checkpoint before/after SFT, evidence-constrained prompting and the exact comparator on identical packets. Report coverage, unsupported findings, invalidity, latency and actual credits. Do not use vendor preference win rate as the audit endpoint.

5. **Verify an evidence-restoration benefit.** Enumerate the minimum authentic add-back witness, compare equal-record random restoration and report the token/record cost per resolved packet. The oracle minimum is a diagnostic lower bound; a deployable selector must use visible data only. Distinguish retrospective reconstruction from live prevention. A null improvement can still explain a useful preservation boundary.

The [AutoScientist create contract](https://docs.adaptionlabs.ai/api/resources/autoscientist/methods/create) exposes iteration/epoch controls, not a documented monetary hard cap; [the MCP guide](https://docs.adaptionlabs.ai/tools/mcp/) says training creation has no estimate mode. A dataset-adaptation estimate does not price training. Do not launch a training job until its charge is bounded within remaining authorized credit and a serving route works. [PEFT inference](https://huggingface.co/docs/peft/en/quicktour) provides a local base-plus-adapter route, not an automatic hosted Adaption deployment. No training has been launched.

Inoculation is a separate training hypothesis. [Wichers](https://arxiv.org/html/2510.05024v1) and [Tan](https://arxiv.org/html/2510.04340v1) change training-time prompts; adding an instruction at inference is not the same intervention. Ordinary correct-label SFT is the first monitor-training comparison. [AI Control](https://arxiv.org/html/2312.06942v4) also cautions against trusting untrusted justifications as monitoring evidence.

The initial observed balance was 1,500 credits, and the user authorized using all available credits for research. Treat this as a staged programme ceiling, with pilot charges included, no top-ups or subscription changes:

| Reproduction, failure liability and robustness |100| Predeclared checks, durable journals and reconciled charges |
| Total initial envelope |**1,500**| Reconcile actual remaining balance before scheduling |

These are allocations, not vendor quotes or instructions to expand a sample after seeing its effect. Reassign an unneeded envelope to a predefined robustness experiment before confirmatory outputs, documenting the change. The cheap fixed pilot shows credits alone are not the bottleneck: task validity, challenge realism, hosted completion behavior and analysis time determine the scope. Do not equate more billed tokens with stronger evidence.

The old 600-episode/26,640-call/252.36-credit profile remains historical costing. Its 2,048-token assumption failed completeness checks and its models were not frozen; it must not be launched as if validated. A new profile must use measured tokens, tail latency/error rates and bounded liabilities, then freeze before confirmation. Final balance reconciliation is still pending after the browser connection failed. Known provider-reported pilot costs and unresolved calls are recorded in PILOT_RESULTS.md.

## What would make the submission stronger

Ship a validated executable evidence contract, real retained model outputs, one clean mechanism/intervention comparison, a transparent failure example and a reproducible negative or positive result. Use previous winners' principles—checkable labels, ablations, useful costs, causal controls and restrained claims—without treating them as a prize formula. Preserve preexisting-work attribution, source versions, AI disclosure and the required ethics appendix. The present development report is reviewable; a full empirical swarm-safety claim is not yet justified.
