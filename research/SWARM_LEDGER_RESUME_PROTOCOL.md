# Router-aware MAIN continuation, version 1

Status: implementation draft; not registered or collecting. Freeze the committed
sources and this protocol, then push `swarm-ledger-resume-v1` before inference.
This operational amendment changes neither the six-reader scientific protocol nor
the original stopped archives. The confirmed daily router reset is at 05:00 GMT
(UTC for this sprint). The original policy had not anticipated this infrastructure
interruption; the new policy is disclosed prospectively rather than attributed
to the original preregistration.

## Immutable prefix and exact remaining cohort

All 8,152 original starts have terminal records: principal 640, coordinator 640,
X 2,560, Y 2,560 and reporter 1,752. The six generic reporter transport/JSON
failures, Y's 43 HTTP 504s and reporter's 51 HTTP 504s remain unchanged. Unknown
usage keeps its entire cost reservation. A terminal failure is never an unstarted
identity and is never resubmitted, even when remote provider completion is unknown.

The new cohort is the exact set difference between each original full phase plan
and the union of all started identities: reporter 808, readers 53,760,
calibration 240 and influence receivers 240, totaling 55,048 remaining calls.
Original job identities, messages, request bodies, models, endpoints, sampling,
ordering, decoding, host execution, evidence oracle, scoring, bootstrap and
independent unit of 640 base blocks remain unchanged. There is no new training,
replacement model, failure-success filter or regeneration of contexts.

Original files stay under `runs/swarm-ledger-v1-main`; all new files go under
`runs/swarm-ledger-resume-v1-main`. No old `stop.json`, driver state, PID, journal,
receipt or registration is modified. The new registration binds the raw hashes
of original metadata files, an aggregate native-receipt inventory commitment, the
original scientific and operational registrations, the new source map and the
remaining-workload forecast. Actual original parent/child termination is checked
using creation-time-safe process identity; no invented PID or lock deletion.

## Request and evidence union

Each new phase plan contains the original full phase identities and exact body
commitment, with the new registration identified separately. The frozen ledger
validates each journal against that full plan. `union_phase` then requires disjoint
original/new starts, exactly one terminal per start, unchanged native receipt
hashes, normalization, host action and costs. Complete analysis requires the full
planned union; a stopped or unresolved continuation phase blocks later phases.

Actor jobs use the original literal actor builder with the authentic union of
earlier actor rows. The reader builder uses the union's actual completed actor
history, including retained invalid failures, to construct the same originally
registered evidence packets. Calibration and influence remain separate frozen
populations. Failed reporters remain invalid notes, not successful statements.

## Bounded outage handling, no inference retries

The shared `collection_connectivity` helper is registered with this collector.
Before initial dispatch and after a classified connection failure, two successful
read-only authenticated catalog checks must occur at least 15 seconds apart.
The daily 04:55–05:05 UTC window blocks new dispatch, allowing existing requests
to drain before the router resets. Each connectivity pause is bounded to 900
seconds, and the unchanged collection cutoff is 9 November 2026 05:59 UTC.

A newly encountered classified connection failure is saved as a terminal failure
with its full reservation. New dispatch pauses, outstanding futures are drained,
and only still-unstarted requests may proceed once health checks pass. At most 32
new classified connection failures are permitted across the continuation; exceeding
that finite allowance stops collection. These failures are not made into
successful calls or excluded from denominators. No SDK or transport automatically
retries a POST. Certificate/TLS, malformed JSON, body-limit, model, capture,
authentication and funding anomalies remain fatal, subject to the helper's explicit
safe classification. A failure while saving a receipt leaves its start unresolved
and blocks automatic continuation.

For future diagnosis, record HTTP status before parsing, stage/exception class,
numeric errno/winerror, safe timing/body-count/hash information and allowlisted
content headers. Never record exception text, credential-bearing headers or raw
answer fragments in diagnostics. Native successful responses remain in the
existing private receipt structure, with source-compatible frozen normalization.

Existing native spacing (one second), per-model limit two, provider native limit
eight, HF/Ollama limits two and global limit eight remain. Existing gateway and
overload waits/Retry-After bounds, the 1,024 per-phase known-gateway allowance,
scientific/native-class budgets, shared Ollama credit-floor guard and excluded
pilot cost lineage are carried forward. Original, engineering, failed-pilot and
continuation costs are summed exactly once. Any unknown usage retains the full
reservation. No account or payment setting is changed.

## Preconditions and validation

The root operator must review and commit all bound sources, complete the new
analysis-admission protocol and remaining cost/time forecast, create the freeze,
tag and push it before any resumed inference. The separate union analysis also
must be registered before fresh data. Tests must demonstrate body parity, strict
disjoint union, duplicate/reissued identity rejection, failed terminal retention,
native/plan tamper rejection, host-action parity, inherited financial holds,
connectivity pause and fatal behavior. Results are not released as complete until
all original-plus-new phases are complete and independently replayed.

The paper will disclose the original stop, network-correlated evidence, this
prospective operational amendment and collection batch timing. All serving
failures remain delivery outcomes, not evidence of model reasoning failure or
swarm misconduct. Track 4's evidence-versus-reasoning comparison, matched cases
and all earlier iterations remain intact. The final Limitations and Dual-Use /
Ethical Considerations appendix remains required.
