# Primary-source scope for a live handoff audit extension

Reviewed 6 November 2026. This is a targeted methods/overlap review, not a systematic originality certificate. The completed scripted study and its null primary finding remain in RESULTS.md. LIVE_AUDIT_PROTOCOL.md specifies the new prospective study; its committed source hashes and live-audit-v1 tag, rather than this review, establish registration. No new model calls or account access were used in this source review.

## Closest methods and what remains to test

| Primary source and reading depth | Existing contribution/assumption | Implication for the proposed extension |
|---|---|---|
| [Yun et al., 2610.09581v1](https://arxiv.org/html/2610.09581v1), reconstruction method, Study II, scoring and discussion | Same-packet readers/comparator, binding availability crossed with identifier spelling, supported findings versus correct guesses | Adopt these distinctions. Neither renaming, restored bindings nor abstention alone supplies novelty. Measure agent-generated workflows and a budgeted, metadata-only acquisition policy. |
| [Qin et al., 2609.30266v1](https://arxiv.org/html/2609.30266v1), §§3.4–4 and completeness | Peer-example tampering and independently controlled recording; completeness requires constraining untraced activity | Keep collector control explicit. Missing export copies are a retention intervention, not an attack that defeats the collector. Generic peer imitation is established prior art. |
| [BRIDGE, 2610.17805v1](https://arxiv.org/html/2610.17805v1), §§3.2–3.5 and Appendix A | Offline paired continuations estimate repair utility; runtime changes are checked before commit | Do not claim the first verified handoff repair. This proposal acquires authentic records for retrospective auditing; it does not repair worker actions or establish improved task completion. |
| [Prompt Infection, 2410.07283v1](https://arxiv.org/html/2410.07283v1), §§3–4, non-replicating control | Propagation through multi-agent messages with global/local communication and explicit compromise assumptions | Actual generated handoffs are a useful stimulus, but a one-hop message perturbation does not establish spontaneous collusion or epidemic spread. |
| [Who&When, 2505.00212v2](https://arxiv.org/html/2505.00212v2), §2 and annotation procedure | Decisive-error responsibility is defined by a corrective intervention changing failure to success | Executor identity is a different label. ## Additional recorder precedents

[Agent Flight Recorder, 2609.01931v1](https://arxiv.org/html/2609.01931v1) was reviewed at its threat model, semantic schema, verification, synthetic evaluation and limitations. It already binds intent, policy, approval, execution, effects and delegation provenance; it separates payloads from metadata and supports selective disclosure. Completeness is explicitly a non-goal. Its synthetic tamper/query results do not demonstrate robustness of LLM readers to missing evidence. The [author repository security policy](https://github.com/mpi-dsg/agent-flight-recorder/blob/main/SECURITY.md) further requires a trusted terminal checkpoint or anchor for meaningful authenticity/truncation claims. Therefore a new signed logger, actor-provenance schema, inclusion proof or relational forensic query would overlap substantially. We are not integrating or independently benchmarking that implementation.

[NovaFabric, 2609.12582v1](https://arxiv.org/html/2609.12582v1) was reviewed at §§2.2, 3.7, 4.1–4.6 and 5.1–5.4. It already offers sealed execution capsules, provenance and replay concepts. Its evaluation distinguishes stored model-response substitution from completing tool-using workloads: only 2/10 completed, because tool replay still reached live I/O. It also reports capture/lineage defects and limits the trusted capture boundary. The evaluation corpus was not publicly downloadable at that version (§4.1); no replication was performed. Our replay must rerun the bounded interpreter with no live calls and verify real state transitions, rather than merely check a clean status or a stable digest. Cryptographic recording and general capsule replay are not our claimed contribution.

The October [NovaFabric technical report, 2610.34594](https://arxiv.org/abs/2610.34594), was abstract-screened only. It explicitly reports no new experiments and points to the September evaluation. It is not counted as an independently reviewed empirical result. Search results for other similarly named commercial “flight recorders” were not used as scientific evidence.

## Inspect conventions: useful interface, explicit denominators

[Inspect custom scorers](https://inspect.aisi.org.uk/custom-scorers.html) document TaskState/Target-to-Score functions and named metric values. [Scoring policy](https://inspect.aisi.org.uk/scoring-policy.html) distinguishes model verdicts, measurement errors and unscored cases; errors/unscored samples can leave default accuracy denominators. A wrapper must retain separate planned-call, transport, parsing and oracle counts rather than silently treating default accuracy as our all-planned-call endpoint. No LLM judge should replace executable fake-state labels.

[Sandboxing](https://inspect.aisi.org.uk/sandboxing.html) explains that arbitrary shell/Python tools need isolation; an evaluation framework does not itself contain arbitrary model text. Here tools should remain a finite in-memory interpreter. An optional Inspect adapter can expose the existing offline cases/scorers and source-group IDs, but framework adoption is not evidence of validity or a reason to delay the core study. The initial metrics-page URL failed extraction; no undocumented clustered-metric behavior is assumed.

## Impact and falsification

The live [Apart rubric](https://apartresearch.com/sprints/swarm-alignment-2026#guidelines) values innovation, execution and clarity. The practical question is whether an investigator can buy useful supported findings with a small authentic-evidence budget on genuine model-produced traces. If metadata retrieval does not outperform a budget-matched random policy, retain that result. If direct and delegated workflows behave alike, do not claim a swarm-specific mechanism. If only prior schema-slot deletion is tested, a preservation result remains constructed rather than general-purpose retrieval. The existing primary null cannot be replaced retrospectively by this new endpoint.
